Rails framework and configuration defaults
==========================================

Baseline
--------
CobbleBot runs Rails 8.1.3.1 with `config.load_defaults 8.1`. Framework
compatibility and each default adoption are validated as separate slices.
Zeitwerk remains explicit, and only the framework railties used by the
application are loaded.

Compatibility declarations
--------------------------
- Message recipient, author, and parent associations remain optional because
  worker-generated IRC replies and other historical records may omit them.
- Link actor remains optional because standalone discovered links are valid.
- The Gist helper and Minotar fallback are intentional cross-host redirects and
  opt in with `allow_other_host: true`.
- JSON parameter wrapping remains in the existing initializer.
- Cookie serialization now comes from the Rails 7 JSON default; the redundant
  application initializer was removed.
- Test exception handling uses the Rails 7.1 `:none` setting instead of the
  deprecated boolean form.
- The legacy `config/secrets.yml` bridge is gone. Production reads
  `SECRET_KEY_BASE` through Rails' supported configuration path; development
  and test use Rails' generated local secret.
- Resque task coverage inspects a clean operator-style Rake process because the
  Rails test runner may reset its in-process task registry after task files have
  already been required.
- Autoloaded application paths are no longer added to `$LOAD_PATH`. Rails keeps
  the application `lib` directory there intentionally, so the existing
  `ApiConstraints` route dependency remains supported without a special shim.
- Active Support writes framework messages as JSON with legacy Marshal read
  compatibility, uses the 7.1 cache format, and embeds message metadata in the
  new envelope. CobbleBot has no shared Rails cache or application cache calls.
- Action View and DOM assertions use HTML5 parsing and sanitization. Default
  response headers use the Rails 7.1 security policy.
- Development and test logs rotate at Rails 7.1's 100 MB local cap. Rotated
  `*.log.*` archives are ignored alongside active logs.
- SQLite strict-string mode and the Rails 7.1 transaction defaults are active.
  CobbleBot has no serialized columns, readonly attributes, secure tokens,
  Active Record encryption, transaction callbacks, or Active Job surface that
  requires a compatibility override.
- Rails 7.2 removed the deprecated parameters-hash equality, non-local
  transaction-return, and singular-association-name compatibility switches.
  CobbleBot did not rely on them; behavior coverage replaces assertions on the
  removed configuration APIs.
- Rails 7.2 adds `useragent` through Action Pack and no other new direct runtime
  surface. Rack 3.2 is independently validated through Rails and Resque Web.
- Rails 7.2 enables migration timestamp validation. Every repository migration
  has a valid timestamp, including the two intentional modernization data
  migrations.
- PostgreSQL raw date values now decode as `Date`; CobbleBot has no schema-level
  `date` columns or raw date-query consumers, and focused PostgreSQL coverage
  verifies the adapter behavior.
- Rails 8.1 disables `config.yjit` in development and test, where code reloading
  and method replacement make it less useful, and enables it in production.
  The locally validated Ruby 3.3.12 build does not expose an enabled YJIT, so
  the production setting is inert there; other deployment builds may enable it.
- The other Rails 7.2 defaults belong to Active Job and Active Storage. CobbleBot
  loads neither railtie, so those configuration surfaces remain absent.
- Rails 8.0 requires Ruby 3.2 or newer; the supported Ruby 3.3.12 runtime is
  already inside that boundary. The Rails framework family moves together to
  8.0.5.1, Active Support adds the maintained `uri` gem, and Rails no longer
  carries its former `cgi` edge.
- CobbleBot uses none of Rails 8.0's removed enum, connection-pool, schema-cache,
  transaction-return, or deprecated Active Support APIs. Sprockets, Resque, and
  the selective-railtie boundary remain explicit; this bridge does not adopt
  Propshaft, Solid Queue, Solid Cache, or unused framework railties.
- Rails 8 defaults preserve the represented time zone through
  `config.active_support.to_time_preserves_timezone = :zone`. CobbleBot has no
  application calls to `#to_time`, so no data or display behavior changes.
- Rails 8 defaults enable strict HTTP freshness. The server-icon endpoint is the
  only Rails conditional-GET surface; when both validators are supplied, a
  matching `If-None-Match` now correctly takes precedence over a stale
  `If-Modified-Since` and returns HTTP 304. Its content ETag and two-hour public
  cache policy remain unchanged.
- Rails 8 defaults set `Regexp.timeout` to one second. Seeded and persisted
  callback patterns remain valid and the callback suite stays green; the worker
  handling boundary already catches `Regexp::TimeoutError` as a standard runtime
  failure instead of allowing a pathological pattern to hang indefinitely.
- Rails 8.1 removes the deprecated statistics constant. Task tests load the
  complete application registry once; a clean `bundle exec rake -P` subprocess
  continues to prove that the operator registry includes Resque and excludes
  the retired Resque Pool hook.
- Minitest 6.0.6 is the supported test runner. Its removed compatibility APIs
  were absent from CobbleBot's tests. Minitest 6 extracted `minitest/mock` into
  the official `minitest-mock` gem, which is pinned to 5.27.0 in the test group;
  the production bundle continues to include only Minitest itself through
  Active Support.
- Rails 8.1 retains the Ruby 3.2 minimum and moves the complete framework family
  to 8.1.3.1. Action Text adds its required `action_text-trix` edge, while
  Active Support drops its direct `benchmark` edge and declares the already
  selected `json` dependency. Unrelated packages remain fixed.
- CobbleBot uses none of Rails 8.1's removed query-parser, SQLite `retries`,
  Active Job, Active Support, or legacy console/statistics APIs. Rails 8.1
  removes `STATS_DIRECTORIES`, so the task-test loader no longer needs the Rails
  8.0 constant-normalization workaround.
- Rails 8.1 replaces the deprecated open-redirect boolean with
  `config.action_controller.action_on_open_redirect = :raise`; the application
  preserves the same cross-host protection and keeps its two intentional
  `allow_other_host` redirects. Rails now always preserves a Time receiver's
  zone, so behavior coverage replaces inspection of the deprecated
  `to_time_preserves_timezone` configuration.
- Rails 8.1 defaults are active without compatibility overrides. JSON documents
  no longer escape HTML characters or modern JavaScript line separators by
  default; CobbleBot serves them as `application/json`, and Haml continues to
  escape JSON placed in HTML attributes. Path-relative redirects now raise, and
  every application redirect uses a URL helper or an explicit absolute URL.
- Order-dependent finders now require an orderable model; every application
  table has a primary key. Action View's Ruby render tracker compiles all 63
  Haml templates, and generated hidden fields safely omit the obsolete
  `autocomplete="off"` attribute.

Deployment note
---------------
Rails 7 changes the application key-generator digest from SHA-1 to SHA-256.
Existing encrypted admin session cookies cannot survive that transition, so the
first deployment logs current admins out once. Operators should simply sign in
again. Preferences, Minecraft state, and other persisted application data are
not changed.

The Rails 7.1 message serializer can read Rails 7.0 Marshal payloads. Older
releases cannot read the new metadata envelope, so rolling back after a new
session is issued may log an admin out again. Resque payloads and Redis keys do
not use the Rails message or cache formats and require no migration or flush.

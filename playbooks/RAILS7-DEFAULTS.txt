Rails 7 configuration defaults
==============================

Baseline
--------
CobbleBot runs Rails 7.2.3.2 with `config.load_defaults 7.2`. Framework
compatibility and default adoption were validated as separate slices. Zeitwerk
remains explicit, and only the framework railties used by the application are
loaded.

Compatibility declarations
--------------------------
- Message recipient, author, and parent associations remain optional because
  worker-generated IRC replies and other historical records may omit them.
- Link actor remains optional because standalone discovered links are valid.
- The Gist helper and Minotar fallback are intentional cross-host redirects and
  opt in with `allow_other_host: true`.
- JSON parameter wrapping remains in the existing initializer.
- Cookie serialization now comes from the Rails 7 JSON default; the redundant
  application initializer was removed.
- Test exception handling uses the Rails 7.1 `:none` setting instead of the
  deprecated boolean form.
- The legacy `config/secrets.yml` bridge is gone. Production reads
  `SECRET_KEY_BASE` through Rails' supported configuration path; development
  and test use Rails' generated local secret.
- Resque task coverage inspects a clean operator-style Rake process because the
  Rails test runner may reset its in-process task registry after task files have
  already been required.
- Autoloaded application paths are no longer added to `$LOAD_PATH`. Rails keeps
  the application `lib` directory there intentionally, so the existing
  `ApiConstraints` route dependency remains supported without a special shim.
- Active Support writes framework messages as JSON with legacy Marshal read
  compatibility, uses the 7.1 cache format, and embeds message metadata in the
  new envelope. CobbleBot has no shared Rails cache or application cache calls.
- Action View and DOM assertions use HTML5 parsing and sanitization. Default
  response headers use the Rails 7.1 security policy.
- Development and test logs rotate at Rails 7.1's 100 MB local cap. Rotated
  `*.log.*` archives are ignored alongside active logs.
- SQLite strict-string mode and the Rails 7.1 transaction defaults are active.
  CobbleBot has no serialized columns, readonly attributes, secure tokens,
  Active Record encryption, transaction callbacks, or Active Job surface that
  requires a compatibility override.
- Rails 7.2 removed the deprecated parameters-hash equality, non-local
  transaction-return, and singular-association-name compatibility switches.
  CobbleBot did not rely on them; behavior coverage replaces assertions on the
  removed configuration APIs.
- Rails 7.2 adds `useragent` through Action Pack and no other new direct runtime
  surface. Rack remains on the compatible 2.2 line.
- Rails 7.2 enables migration timestamp validation. Every repository migration
  has a valid timestamp, including the two intentional modernization data
  migrations.
- PostgreSQL raw date values now decode as `Date`; CobbleBot has no schema-level
  `date` columns or raw date-query consumers, and focused PostgreSQL coverage
  verifies the adapter behavior.
- `config.yjit` is enabled. Rails only activates YJIT on Ruby builds that expose
  it. The locally validated Ruby 3.3.12 build does not, so this needs no
  compatibility override; deployment builds may enable it when available.
- The other Rails 7.2 defaults belong to Active Job and Active Storage. CobbleBot
  loads neither railtie, so those configuration surfaces remain absent.

Deployment note
---------------
Rails 7 changes the application key-generator digest from SHA-1 to SHA-256.
Existing encrypted admin session cookies cannot survive that transition, so the
first deployment logs current admins out once. Operators should simply sign in
again. Preferences, Minecraft state, and other persisted application data are
not changed.

The Rails 7.1 message serializer can read Rails 7.0 Marshal payloads. Older
releases cannot read the new metadata envelope, so rolling back after a new
session is issued may log an admin out again. Resque payloads and Redis keys do
not use the Rails message or cache formats and require no migration or flush.

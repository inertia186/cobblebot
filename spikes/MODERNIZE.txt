CobbleBot modernization spike
============================

Purpose
-------
Record the conclusions from the preservation and modernization experiments. This
is evidence for choosing the next migration step, not a final project roadmap.

Current baseline (2026-08-06)
-----------------------------
- Branch: `develop`.
- Ruby `3.3.12`, Bundler `2.6.6`, and Rails `7.2.3.2` resolve and boot with Rails
  7.2 configuration defaults.
- Rails 7/Ruby 3 is the only supported lane. Rails 4/Ruby 2.6 remains in git
  history but is not maintained, tested, or kept reproducible.
- `bundle check` passes.
- The Rails environment boots when the configured local Redis is available.
- Normal Rails initialization no longer inspects or mutates Resque, so web,
  console, route, migration, and asset commands can boot when Redis is absent.
  Operators seed the watchdog explicitly with
  `rake cobblebot:workers:bootstrap`; the existing five-minute schedule remains
  the periodic safety net.
- Rails explicitly uses Zeitwerk, and `RAILS_ENV=test bundle exec rails
  zeitwerk:check` passes.
- CobbleBot loads only the Rails, Active Model, Active Record, Action Controller,
  Action View, Rails test-unit, and Sprockets railties it uses. Unused framework
  engines no longer contribute boot requirements or routes.
- `Gemfile.lock` contains the native `arm64-darwin-24` platform variants for
  Nokogiri, PostgreSQL, and SQLite.
- Static web dependencies are vendored under `vendor/assets/`; the old live
  `rails-assets.org` path is disabled.

What the preservation spike established
----------------------------------------
- Ruby 3.2 cannot use Bundler 1.16.1 because the old Bundler calls removed taint
  APIs. Modern Bundler also cannot resolve the original Rails 4.2 dependency
  boundary unchanged.
- Ruby `2.7.8` gets through old Bundler resolution but cannot compile
  `nokogiri 1.8.4` with the current Apple toolchain, even with system libraries.
- Ruby `2.6.10` is the viable preservation lane on this host. Nokogiri 1.8.4 can
  be installed with system libraries there.
- The next old-stack failure was `ffi 1.9.25`, pulled through the Sass asset
  branch rather than the Minecraft log-monitor runtime.
- Vendoring the required CSS, JavaScript, fonts, and images allowed the old
  Sass/bootstrap/rails-assets branch to be removed.
- On the preservation lane, bundle restore, Rails 4.2 boot, asset precompile,
  database migration, seeding, and a live server/admin-login smoke test all
  succeeded.
- The root page then reached ordinary application behavior: it rendered the
  server-down path because no live Minecraft server was configured.

What the modernization spike established
-----------------------------------------
- Rails can advance to `6.1.7.10` on Ruby `3.2.7` without first redesigning the
  application.
- Several dependencies needed upgrades (`json`, `sqlite3`, `pg`, `mechanize`,
  `responders`, `haml`, `will_paginate`, and `byebug`). Obsolete development,
  documentation, and test gems were disabled where preserving them added no
  value.
- Requiring `logger` before the explicit Rails railties remains a compatibility
  shim.
- Zeitwerk found one confirmed naming mismatch: `banned_ip.rb` now defines
  `BannedIp`. No compatibility alias was needed because the repository had no
  callers of the old constant.
- The obsolete Slack integration was retired instead of carrying its disabled
  client dependency into the new baseline. Its model, worker hooks, controller
  endpoint, route, admin UI, JavaScript handling, preference keys, stubs, and
  feature coverage are gone. Migration `20260802000000` irreversibly deletes
  persisted `slack_api_key` and `slack_group` rows.
- Rails test support on Ruby 3.2 now pins Minitest 5 and supplies REXML. Focused
  preference, migration, watchdog, gametick, and routing tests pass against a
  disposable SQLite database.
- The authenticated admin preferences smoke exposed the old Jbuilder template
  handler boundary; Jbuilder 2.13 resolves it without widening the existing 2.x
  Gemfile constraint.
- Adding the native macOS arm64 platform to the lockfile avoids unnecessary
  source builds for Nokogiri and other native gems.
- The modern stack no longer includes `sassc-rails`, `sassc`, or native FFI.
  The historical SCSS entrypoint is archived under `docs/archive`, outside the
  asset load path. A clean production precompile exposed and fixed missing
  digested Glyphicons/Chosen references by publishing vendor font/image trees
  and using Sprockets ERB asset paths in the two affected stylesheets.
- `MinecraftWatchdogBootstrap` now owns immediate, repeatable watchdog seeding.
  It skips a watchdog that is already queued or running and fails clearly when
  an operator invokes it without Redis.
- Resque job serialization now uses a Ruby-3-compatible MultiJson release; the
  previously locked 1.13 release failed before a job could reach Redis.
- Redis configuration now has one lazy owner with explicit URL and namespace
  overrides. Operational environments retain database 1, tests use database 3,
  and a process-specific namespace proves real enqueue serialization without
  disturbing unrelated queues.
- Dentaku 3.5 originally restored the Calc callback on Ruby 3. Whole-number
  results retained the concise historical display, and the complete worker
  suite passed without the former `BigDecimal.new` failure or nil-assertion
  deprecation flood.
- The watchdog is now a one-shot scheduled maintenance job. A Redis-independent
  `MinecraftWorkerQueuePolicy` converges the log-monitor and optional IRC queues
  to one canonical pending standby without inspecting or changing unrelated
  queues. The monitor's five-minute managed lifetime is bounded only by ticks;
  watchdog self-replenishment, sleeps, and queue-depth loops are gone.
- The Rails-internal SQLite transaction monkey patch is retired. Development
  and production now preserve its `BEGIN IMMEDIATE` intent through sqlite3's
  supported `default_transaction_mode`, with the existing 15-second native busy
  timeout. PostgreSQL test configuration remains free of SQLite-only options.
- The Rails 6 controller harness is restored: 90 controller tests run without
  failures or errors, with only the two intentional donation skips. Modern
  request keywords and `rails-controller-testing` preserve the focused
  assertions.
- PhantomJS, Poltergeist, capybara-angular, and their install/log side effects
  are retired. Capybara defaults to `rack_test`; the 21 acceptance tests use
  Selenium with headless Chrome only when explicitly selected, and pass without
  failures, errors, or skips on disposable SQLite.
- Restoring browser coverage also confirmed the current Angular bootstrap,
  permitted sort/status parameters, donation author JSON, and explicit JSON
  template-format boundaries.
- The complete 329-test suite passes against PostgreSQL with 2827 assertions,
  no failures or errors, and six existing skips. Test-only SQLite connection
  pools are removed—not merely disconnected—so they cannot leak into later
  PostgreSQL fixture transactions.
- Production minification exposed and fixed unannotated dependency injection in
  the vendored cancel-on-navigate Angular module. The minified bundle now boots
  Angular through all 21 headless-Chrome acceptance tests.
- Application-owned Rails and Minitest deprecations are removed. The test
  environment raises on future Active Support deprecations, nil JSON values use
  the Minitest 6-compatible assertion path, and the seeded callback sweep no
  longer starts delayed production threads that outlive the test. SimpleCov 0.22
  has an explicit suite name and metric-based coverage-floor configuration.
- The Rails 6.1 positional-coder warning against modern pg was left visible
  rather than suppressed or patched through private adapter methods. Advancing
  to Rails 7.0.10 subsequently removed it.
- Reachable controller and supporting-model coverage now protects admin IPs and
  server properties, the public IRC count and server icon, reputation API
  projections, IP queries, IRC reply retention, and active callback parsing.
  The incomplete API session and obsolete development console routes were
  retired. `rake cobblebot:test:coverage` disables result merging and enforces a
  75% complete-suite floor; the measured PostgreSQL baseline is 372 tests, 2962
  assertions, six skips, and 76.20% coverage on the Rails 7 relevant surface.
- The supported package lane now targets CRuby only. Obsolete JRuby/JDBC
  dependencies and the Java lock platform were nonfunctional on Rails 6.1 and
  blocked modern Bundler resolution, so they were retired before a strict
  patch-level dependency refresh. Resque Scheduler 4.11, Redis Namespace 1.8,
  Redis Store 1.6, and their timing dependencies now pass real namespaced Redis
  scheduling and queue-policy tests. Redis 3 and Resque 1 remain fixed for a
  separate core compatibility slice; MultiJSON is capped below 1.21 until then
  because Resque 1 calls aliases deprecated by that release.
- Rails now runs on the final Rails 7.0 maintenance release. Sprockets Rails is
  an explicit dependency because Rails 7 no longer supplies it through the
  meta-gem, and Active Record uses the Rails 7 connection handler. The upgrade
  removes the former Rails 6.1/pg coder warning.
- Rails 7 configuration defaults are fully loaded. Optional historical
  `Message` and `Link` associations and intentional cross-host redirects are
  explicit, JSON parameter wrapping remains supported, and the obsolete cookie
  serializer initializer is gone. The SHA-256 key-generator transition causes
  a one-time admin-session cookie rollover on deployment but does not alter
  persisted application data.
- The complete Rails 7 PostgreSQL gate passes 383 tests and 2997 assertions
  with no failures or errors and six intentional skips. SimpleCov measures
  76.37% of the Rails 7 relevant surface, above both the documented 76% target
  and the enforced 75% floor.
- The Redis client boundary now runs on redis-rb 5.4.1, Resque 3.0.0, Resque
  Scheduler 5.0.0, and Redis Namespace 1.11.0. Redis Store and Vegas are gone,
  MultiJSON 1.21.1 is uncapped, and CobbleBot bridges Resque 3.0's deprecated
  serializer aliases to the maintained API without changing payloads. Real
  namespaced Redis tests prove old-payload reads, rollback-compatible writes,
  schedule persistence, active-worker detection, queue policy, and authenticated
  Resque Web access; a disposable worker process also forks and exits cleanly.
- The one callback-only Git dependency is retired. `McSlap` now lives under
  Zeitwerk with the original phrase data and deterministic sampling coverage;
  clean installs and rollback bundles no longer require GitHub SSH host-key
  trust, and Rails/test boot no longer emits the Gist's stderr banner.
- ai4r 2.0 preserves CobbleBot's ID3 dataset and evaluation API on Ruby 3.2.
  Prediction classifiers now handle empty and unseen training data explicitly,
  rebuild from current database rows instead of leaking a process-global cache,
  and retain the in-game `Cannot predict` response without hiding programming
  errors behind broad callback rescues.
- The repository no longer ships an incomplete God process definition or a
  server-specific tmux recipe. README records one supervisor-neutral command
  for each web, scheduler, bootstrap, watchdog, monitor, and optional IRC
  process; deployment-specific systemd policy remains outside the application.
- Summer remains the supported optional IRC integration. Sting chat is deferred
  as a separate feature rather than replacing or reshaping Summer during
  dependency modernization.
- The remaining Rails-7.0-compatible dependency set is current under Bundler's
  strict resolver. Better Errors, Jbuilder, JSON, Responders, Crack, ExecJS,
  Launchy, NKF, Public Suffix, Tilt, and Tins are refreshed without moving
  Rails, Summer, ai4r, Redis/Resque, file-tail, or Minecraft Query. Tins' larger
  Ruby-3.2-compatible support graph is accepted and covered at the real file
  rotation boundary.
- Rails 7.1.6 is a compatibility bridge rather than a defaults migration.
  `config.load_defaults 7.0`, selective railties, Redis-independent boot, and
  the public route surface remain unchanged. The deprecated secrets-file path
  is retired in favor of `SECRET_KEY_BASE` and Rails local secrets, test
  exception handling uses `:none`, and Resque task coverage now observes a
  clean Rake process. PostgreSQL, real Redis, assets, and headless Chrome remain
  green.
- Rails 7.1 defaults are now active. The application does not depend on the
  affected Active Job, Active Record encryption/serialization/readonly/token,
  transaction-callback, or shared-cache surfaces. Focused coverage protects the
  JSON-with-Marshal-fallback message serializer, HTML5 parsing/sanitization,
  strict SQLite behavior, response headers, the 100 MB local log cap, and
  supported `lib` route loading. Rotated log archives are ignored.
